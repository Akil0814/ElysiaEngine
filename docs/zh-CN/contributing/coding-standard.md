# Elysia 引擎层代码规范

## 代码命名规范

- 类、结构体、枚举使用 `PascalCase`
- 枚举项使用 `PascalCase`
- 私有及受保护成员变量使用 `_name_name`
- 公开数据成员使用 `name_name`
- 局部变量及函数参数使用 `name_name`
- 函数、成员函数使用 `name_name`
- 文件名及命名空间使用 `name_name`
- 普通 `const` 变量遵循对应作用域的命名规范
- 编译期命名常量使用 `kPascalCase`
- 宏使用 `ELYSIA_UPPER_SNAKE_CASE`

### 类与类型命名规范
- 类名应使用名词或名词短语，准确描述其职责。
- 不使用 `C`、`I`、`S` 等匈牙利式类型前缀。
- 抽象类与接口不强制添加 `Abstract`、`Base` 或 `I` 前缀。
- 只有当 `Base` 能明确表达类型职责时才使用。
- 类型缩写按普通单词处理，例如 `UiWindow`。
- 模板类型参数使用 `T` 或 `TName`。
- 类型别名使用 `PascalCase`
#### Manager
- `Manager`：用于引擎内部，负责对象或资源的生命周期管理、状态维护及相关模块的协调。
- `Manager` 原则上不直接暴露给游戏层，并非所有`Manager`都是单例实现。
#### Service
- `Service`：用于向游戏层暴露引擎能力，提供明确的操作接口，隐藏内部管理机制与实现细节。
- 并非所有向游戏层暴露的类都需要 `Service` 后缀，数据类型、对象模型等仍根据其实际职责命名。


## 生命周期命名规范

- `initialize()` / `shutdown()`：建立和销毁模块的可用状态
- `start()` / `update()` / `reset()`：启动、推进和重置持续运行或异步流程
- `load()`：从文件或其他外部数据源读取内容
- `configure()`：更新配置，不负责完整模块生命周期
- `bind()`：注入或连接运行时依赖
- `is_initialized()`：查询模块是否已经完成初始化

不要仅为了统一形式而把具有运行流程语义的 `start()`，或具有数据读取语义的
`load()` 改成 `initialize()`。初始化与关闭应成对设计；如果模块公开初始化状态，
状态查询统一使用 `is_initialized()`。

## auto 使用约定

- 默认优先显式声明类型，尤其是引擎公共 API 及核心逻辑。
- 当类型无法直观判断时，不使用 `auto` 隐藏类型信息。
- 迭代器、泛型代码、Lambda、智能指针工厂等场景允许使用 `auto`。
- 使用 `auto` 时，不应隐藏重要的指针、引用或所有权语义。
- 不应仅为了减少代码长度而使用 `auto`。

## 代码完整性要求

- 确保每次提交的源码必须处于可编译状态
- 未完成实现标注 `TODO`
- 未实现功能不得伪装成正常执行结果。
- 修改已有功能时，应确保相关测试通过。


## 错误处理规范

- 文件、配置、资源和可恢复操作的预期失败使用 `[[nodiscard]] std::expected`，调用方必须消费结果。查询不存在、可选效果或播放拒绝可保留明确的空值或状态结果。
- 跨层传播使用 `FailureDiagnostic`，保留原始来源、资源键、声明位置和恢复错误。不要只提取消息后重新生成诊断；普通异常记录捕获位置，不能声称它是原始抛出位置。
- 场景逻辑异常由 SceneManager 捕获、执行清理并进入 ApplicationFailureScene。恢复失败只通知故障，不递归恢复；故障观察者互相隔离，通知失败也必须记录。
- SDL 渲染状态读取、绘制、恢复、清屏或提交失败统一进入应用故障退出；恢复已修改状态后停止命令执行，不再尝试用同一渲染器显示失败场景。
- 工作线程必须有入口异常边界，将首个异常及任务上下文交回主线程。线程中不执行全局清理；主线程停止派发、回收全部线程并清理半成品。
- 多步骤修改失败后必须恢复实际状态，不能仅依赖配置值变化触发恢复。恢复继续尝试其他步骤，同时保留原始失败与恢复失败。
- Logger 负责记录，不负责退出。完整诊断在处理边界写入日志；TerminationManager 保留首个退出请求，复制有界文本并标记截断，Application 完成统一关闭。
- 只有真正保证不抛异常的路径才标记 `noexcept`。包含分配或需要传播异常的渲染辅助函数不能依靠 `noexcept` 吞掉错误；关闭边界捕获失败、继续清理并返回关闭结果。
- 删除旧契约时同步迁移引擎、游戏、测试和文档调用，不保留未经授权的兼容包装。
