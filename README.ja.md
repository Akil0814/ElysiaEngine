Elysia Engine は、C++23 と SDL3 で構築されたモジュール式の 2D ゲームエンジンおよびランタイムフレームワークです。アプリケーションのライフサイクル管理、シーンルーティング、リソース管理、入力、描画、オーディオ、UI、物理、セーブデータなど、ゲームに共通する機能を提供します。

このリポジトリには、再利用可能なエンジン実装とサンプルアプリケーションの両方が含まれています。`engine/` はエンジン機能を提供し、`game/` はゲームモジュールとエンジンの統合例を示します。ビルドで生成される `ElysiaEngine` 実行ファイルは、このサンプルアプリケーションを実行します。エンジン実装とゲームロジックは分離されており、それぞれ独立して拡張・保守できます。

## 主な機能と現在の状況

- **アプリケーションとシーン**：アプリケーションのライフサイクル管理、シーンの登録とルーティング、ゲームモジュールの統合境界を提供します。
- **リソースと設定**：リソースマニフェスト（manifest）、コンテンツ登録、実行時設定、国際化、ユーザー設定サービスを提供します。
- **入力と Gameplay**：デバイスの生入力、アクションマッピング、プレイヤーコントローラー、固定 tick でのコマンド処理、シーンへの入力ルーティングを提供します。
- **描画と UI**：SDL3 GPU renderer、リテインモード UI、レイアウト、フォーカス、ウィンドウサーフェス、スタイル、ウィジェットを提供します。
- **オーディオとカメラ**：オーディオリソースの再生スケジューリング、カメラスロット、追従、画面シェイク、座標投影を提供します。
- **物理とセーブデータ**：Box2D 統合、衝突処理と Gameplay ランタイム、型付きセーブデータ、信頼性の高い復旧機能を提供します。
- **アニメーションとエフェクト**：アニメーションリソース、アトラス、`EffectDefinition` による設定を提供します。
- **開発支援**：Demo Gallery、任意で有効化できる Dear ImGui 開発用オーバーレイ、サブシステム別のユニットテストと統合テストを提供します。

**ネットワーク機能の制限**：ENet は現在、エンジンがリンクするトランスポート層の依存ライブラリとしてのみ組み込まれています。ネットワークセッション、状態同期、ネットワーク経由のマルチプレイは未実装です。

## リポジトリ構成と依存関係の境界

- `engine/`：再利用可能なエンジン実装です。`engine_lib` としてビルドされます。
- `game/`：ゲームモジュールとサンプルシーンを提供する統合例です。`game_lib` としてビルドされます。
- `assets/`：サンプルアプリケーションとエンジン組み込みの処理で使用する設定、フォント、オーディオ、テクスチャを格納します。
- `tests/`：サブシステム別のユニットテストと統合テストを格納します。
- `docs/`：ユーザーガイド、アーキテクチャの説明、貢献ガイド、設計ドキュメントを格納します。
- `thirdparty/`：リポジトリに同梱されたサードパーティの依存ライブラリを格納します。

主な依存関係の方向は次のとおりです。

```text
ElysiaEngine executable -> game_lib -> engine_lib
                                      -> SDL3 libraries
                                      -> Box2D
                                      -> ENet
```

エンジン層は `game/` に依存しません。ゲームロジックは `IGameModule` を通じてアプリケーションの記述とシーン登録を提供し、ゲーム固有の型はゲームモジュールで管理します。


## クイックスタート

### 必要な環境

以下の手順では、Windows、MSVC x64、Visual Studio のマルチ構成ジェネレーターを使用します。必要な環境は次のとおりです。

- CMake 3.24 以降が必要です。
- C++23 に対応した MSVC ツールチェーンが必要です。
- SDL3 GPU renderer に対応したグラフィックスデバイスとドライバーが必要です。GPU renderer の作成に失敗した場合、アプリケーションはエラーを報告して終了し、ソフトウェア描画へ自動的に切り替わることはありません。

SDL3、image、ttf、mixer、gfx、および必要なコーデックは、すべてリポジトリに同梱された固定バージョンのソースからビルドされます。通常の構成・ビルド時に依存ライブラリをダウンロードすることはありません。バージョンとローカルパッチについては、[依存ライブラリのソース情報](thirdparty/SDL3-DEPENDENCIES.md)を参照してください。

### ビルドと実行

リポジトリのルートで実行します。

```powershell
cmake -S . -B out/build/sdl3-Debug -A x64
cmake --build out/build/sdl3-Debug --config Debug --parallel
.\out\build\sdl3-Debug\Debug\ElysiaEngine.exe
```

リソースを正しく読み込めるよう、実行時の作業ディレクトリをリポジトリのルートにし、`assets/` のディレクトリ構造を維持してください。

Dear ImGui 開発用オーバーレイは、デフォルトで有効です。無効化の方法、Release 構成、Ninja を使ったビルドについては、[ビルド・実行・テスト](docs/ja/user-guide/build-and-run.md)を参照してください。

> 旧バージョンから移行する場合は、SDL2 のビルドキャッシュを再利用せず、新しい SDL3 用ビルドディレクトリを使用してください。ジェネレーターやアーキテクチャを変更する場合も、別のディレクトリを使用してください。

### テストの実行

ビルド完了後に実行します。

```powershell
ctest --test-dir out/build/sdl3-Debug -C Debug --output-on-failure
```

GPU テストには実際のグラフィックスデバイスが必要で、dummy video ドライバーは使用できません。ラベル別のテスト実行、ディスプレイのない環境でのテスト方法、トラブルシューティングについては、[ビルド・実行・テスト](docs/ja/user-guide/build-and-run.md)を参照してください。

### その他のプラットフォーム

Linux、macOS、MinGW でも、リポジトリに同梱された同じ固定バージョンの依存ソースを使用します。ただし、現時点ではこれらの環境での実機検証は行われておらず、Windows でのビルド結果を他のプラットフォームの検証結果とみなすことはできません。ツールチェーンとシステム依存ライブラリの要件については、[詳細なビルド手順](docs/ja/user-guide/build-and-run.md)を参照してください。
